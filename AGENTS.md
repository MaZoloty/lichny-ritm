# Project Memory: «Личный ритм»

Этот файл хранит общие правила по проекту для Codex / Claude Code. Использовать как контекст перед визуальными и UX-задачами.

Эти визуальные правила относятся только к приложению «Личный ритм». Не переносить этот стиль, тексты, палитру и UI-подход на другие проекты без отдельного явного запроса.

## Главный принцип

Проект нельзя переписывать заново. Любые изменения должны быть аккуратными, безопасными и совместимыми с уже работающей логикой.

Если есть выбор между:

1. сделать красивее, но рискнуть логикой;
2. сделать чуть проще, но безопасно;

выбирать второй вариант.

## Нельзя трогать без отдельного явного запроса

- бизнес-логику;
- расчёты;
- Supabase schema;
- server actions;
- auth;
- структуру данных;
- рабочие пользовательские сценарии;
- модуль `/finance` без отдельного аккуратного задания.

## Можно трогать в визуальных задачах

- стили;
- UI-компоненты;
- layout;
- визуальную иерархию;
- отступы;
- типографику;
- карточки;
- кнопки;
- progress bars;
- empty / calm / info states.

## Визуальное направление

Интерфейс должен ощущаться как личное приложение для спокойного контроля жизни:

- мягкий;
- чистый;
- современный;
- спокойный;
- mobile-first;
- premium/editorial;
- женственный, но не слащавый;
- минималистичный, но не пустой.

Не делать приложение похожим на:

- банковский кабинет;
- жёсткий productivity tracker;
- техно-дашборд;
- перегруженный wellness-шаблон;
- детский милый трекер.

## Палитра

Использовать мягкую светлую палитру:

- основной фон: тёплый молочный / кремовый, около `#FAF7F2`;
- карточки: почти белый / молочный, около `#FFFDFB`;
- дополнительные мягкие зоны: около `#F3EEE7`;
- основной текст: тёмный графит, около `#2F2F35`;
- вторичный текст: приглушённый серо-лиловый, около `#7C7A88`;
- третичный текст: светлее, около `#A8A6B2`;
- акцент: мягкий lavender/violet, около `#8B5CF6`;
- фон акцента: около `#EFEAFE`;
- границы: тёплые, почти незаметные, около `#EDE7DF`;
- успех: мягкий зелёный, не кислотный;
- расход/warning: тёплый персиковый/коралловый, без тревожного красного.

Избегать кислотных цветов, тяжёлых тёмных блоков, яркого glassmorphism и heavy shadow.

## Типографика и текст

- Заголовки крупные и понятные, но не кричащие.
- Цифры и суммы должны хорошо читаться.
- Вторичный текст мягкий, но читаемый.
- Минимум мелкого текста.
- `eyebrow`/маленькие подписи использовать только когда они реально помогают.

Не добавлять лишние служебные слова:

- «обзор»;
- «разделы»;
- «быстро»;
- «фраза дня»;
- «мягкий режим», если это не настоящая функция.

Тон интерфейса: короткий, человечный, спокойный, без давления.

Не использовать тексты в духе:

- «провал»;
- «ошибка»;
- «вы ничего не сделали»;
- «отстаёшь»;
- «нужно срочно».

Подходящий тон:

- «Сегодня можно отметить главное»;
- «Маленький шаг тоже считается»;
- «Ты уже движешься»;
- «На сегодня всё спокойно».

## Главный экран

Главная должна быть спокойной точкой входа в день: короткая сводка без перегруза, красивая, но функциональная.

### Hero

Hero должен быть аккуратной карточкой дня.

Структура:

1. `Привет, {имя}`;
2. ежедневная фраза сразу после приветствия, без лейбла;
3. главный заголовок: текущий удачный вариант `В своём ритме`;
4. короткий подзаголовок, например `Маленькие действия складываются в спокойную систему.`

В hero не должно быть:

- дублирования нижнего меню;
- лишних тегов и бейджей ради красоты;
- слова «Мягкий режим», если это не функция;
- ощущения рекламного баннера;
- лишних иконок и декоративных чипов.

Фраза дня:

- хранится локально в коде;
- меняется по дням;
- без API и базы;
- без подписи «Фраза дня»;
- спокойная, взрослая, поддерживающая;
- не инфоцыганская, не эзотерическая, не приторная.

### Действия

Быстрые действия:

- Доход;
- Расход;
- Отметить;
- Пополнить.

Требования:

- сетка 2×2;
- карточки самостоятельные и приятные для нажатия;
- иконка в круге;
- заголовок + короткий подзаголовок;
- не писать сверху слово «Быстро».

### Карточки модулей

Модули:

- Финансы;
- Привычки;
- Цели;
- Долги;
- Сбережения;
- Напоминания, если уместно.

Карточки должны быть компактными, читаемыми, с крупным главным смыслом и без перегруза цифрами. Не дублировать очевидное: если карточка называется «Финансы», не добавлять рядом служебную подпись «Раздел».

### Напоминания

Блок «Сегодня важно» можно оставлять, потому что это смысловой блок.

Если напоминаний нет, показывать спокойное красивое empty state без тревожного тона.

## Финансы

Экран `/finance` обновлять отдельно и осторожно. Прошлый редизайн финансов ухудшил экран, поэтому:

- не трогать `/finance` в общих визуальных задачах;
- сохранять удачные решения прошлой версии;
- не ухудшать читаемость;
- не перегружать интерфейс;
- сначала делать одну аккуратную версию, а не полную переделку.

## Этапность визуальной полировки

1. Сначала довести главный экран.
2. После утверждения главной тем же языком обновлять `/habits`, `/goals`, `/debts`, `/savings`, `/reminders`, `/settings`.
3. `/finance` отдельно и осторожно.

## Критерии приёмки

Результат хороший, если:

1. экран стал заметно красивее;
2. стало чище;
3. стало меньше лишних слов;
4. улучшилась визуальная иерархия;
5. экран выглядит как целостное приложение, а не набор блоков;
6. логика не сломалась;
7. текст не давит;
8. интерфейс ощущается premium и спокойно;
9. главный экран хочется открывать каждый день;
10. мобильная вёрстка выглядит аккуратно.

## Формат отчёта после задач

В конце работы кратко указать:

- какие файлы изменены;
- что визуально изменено;
- что не трогалось;
- прошёл ли `npm.cmd run build`, если запускался;
- что проверить вручную.
